# 🔄 Subset Construction — NFA ➜ DFA

Implementation of the **Subset Construction** presented in
*Kozen, Dexter C. (1997). Automata and Computability, Lecture 6*,
for Assignment 2 of the course **SI2002 Formal Languages**.

Given a nondeterministic finite automaton `N = (Q, Σ, Δ, S, F)`, the program builds
the deterministic finite automaton `M` that accepts exactly the same language, prints
its transition table, and additionally renders both automata as diagrams in an HTML
report (the optional feature of the assignment).

## 📥 Input format

Exactly the format described in Section 3 of the assignment:

1. A line with a number `c > 0`: how many cases follow.
2. For each case, a line with `n > 0`: the number of states. States are `1, 2, …, n`.
3. A line with the initial states `S`, separated by blanks.
4. A line with the alphabet `Σ` (lowercase latin letters), separated by blanks.
5. A line with the final states `F`, separated by blanks.
6. `n` lines, one per state and in order, each one a row of the transition table of `N`.
   Every cell is either `0` (the empty set `∅`) or a set written as `{q1 q2 …}`.
   The symbols appear in the same order given in step 4.

### Example (`input.txt`, the automaton of the assignment)

```
1
5
3 5
a b
1 4
1 {1 5} 0
2 {1} 0
3 {2 4} 0
4 0 {5}
5 {1 5} {4}
```

This is the NFA with `Q = {1,2,3,4,5}`, `Σ = {a, b}`, `S = {3, 5}` and `F = {1, 4}`.

## 📤 Output format

For each case the program prints the transition table of the DFA `M`, with:

- `->` marking the **initial state** of `M`,
- `<-` marking the **final states** of `M`,
- the renamed state (`A0`, `A1`, …), the subset of `Q` it stands for, and one
  column per symbol of `Σ` holding the target state.

No extra blank lines are printed, as required by the assignment.

### Output for the example above (excerpt)

```
       state       a   b
   A0  0           A0  A0
<- A1  {1}         A9  A0
   A2  {2}         A1  A0
   A3  {3}         A11 A0
<- A4  {4}         A0  A5
   A5  {5}         A9  A4
   ...
-> A14 {3 5}       A28 A4
   ...
<- A31 {1 2 3 4 5} A28 A15
```

The initial state is `A14 = {3, 5} = S`, and every subset that intersects
`F = {1, 4}` is final.

## 🧠 The algorithm (Kozen, Lecture 6)

Given the NFA `N = (Q, Σ, Δ, S, F)`, the subset construction produces the DFA

```
M = (2^Q, Σ, δ, S, F')
```

where

- **States:** `2^Q`, the power set of `Q`. Every state of `M` is a *set* of states of
  `N`, and it represents "all the states `N` could be in right now".
- **Transition function:** for a subset `A ⊆ Q` and a symbol `a ∈ Σ`,

  ```
  δ(A, a) = ⋃ Δ(q, a)   for every q ∈ A
  ```

  i.e. the union of everything reachable from any state of `A` reading `a`.
  This is a *total function*, so `M` is deterministic. Note that
  `δ(∅, a) = ∅` for every `a`, which makes `∅` a dead state.
- **Initial state:** the set `S` of initial states of `N` — a single state of `M`,
  which is exactly how the nondeterminism of several starting points disappears.
- **Final states:** `F' = { A ⊆ Q | A ∩ F ≠ ∅ }`, because `N` accepts a string when
  *at least one* of the states it can end in is final.

By induction on the length of the string, the extended transition functions satisfy
`δ̂(S, x) = Δ̂(S, x)` for every `x ∈ Σ*`, so `M` accepts a string exactly when `N`
does: **L(M) = L(N)**.

Nothing outside Lecture 6 is used: there are no ε-transitions (and therefore no
ε-closures), and no state-minimization algorithm is applied.

**Complexity:** `O(2^n · |Σ|)` states and transitions, where `n = |Q|`.

### Steps in the code (`main.py`)

| Step | Function |
| --- | --- |
| Read and parse the cases | `read_cases`, `tokenize`, `parse_set` |
| Enumerate `2^Q` | `power_set` |
| Build `δ`, the initial state and `F'` | `subset_construction` |
| Rename the states as `A0, A1, …` | `name_states` |
| Print the table | `print_dfa`, `dfa_rows` |
| Draw the diagrams | `render_svg`, `nfa_svg`, `dfa_svg` |
| Build the HTML report | `render_html` |

### 📋 Full table vs. 🖼️ diagram

- The **table** lists the states as the construction produces them: the whole power
  set `2^Q`, renamed `A0, A1, …` as the assignment allows.
- The **diagram** draws only the states **reachable** from the initial state
  (found with a breadth-first search using the very same `δ`). This is only a
  drawing decision so the picture stays readable — the algorithm itself is untouched.
- In `output.html` the same distinction splits the DFA into two tables: the reachable
  states and the unreachable ones. For the example, 7 of the 32 subsets are reachable
  and the other 25 are garbage states.
- Safety valve: if `n > 12` the power set (more than 4096 rows) is too big to print,
  so for such cases the table shows only the reachable states and the HTML report
  states why.

## 🎨 Extra feature: automata diagrams

`output.html` is regenerated on **every run** and contains, for each case:

- the **diagram of the NFA `N`**, with an incoming arrow on each initial state and
  double circles on the final states;
- the **diagram of the DFA `M`**, drawing only the reachable states, each node
  labelled with its new name only (`A0`, `A1`, …) and all nodes drawn at the same
  size; a **legend** below the diagram maps every name to the subset of `Q` it
  represents;
- the **transition table of `N`** exactly as it was given as input;
- the **transition table of the reachable states of `M`** — the states that are
  actually used — with `→` for the initial state and `←` for the final ones;
- a second, collapsible **table with the unreachable ("garbage") states of `M`**:
  subsets that the construction creates because it enumerates all of `2^Q`, but that
  no string can ever reach. Both tables together are exactly the full power set.

Colour code of the diagrams: blue for ordinary states, green for final states
(drawn as double circles) and grey for the dead state `∅`.

The diagrams are **SVG drawn by the program itself** (`render_svg`), not by a
diagramming library, so the routing of the arrows can be kept clean:

- **states are organised in levels**: each one goes in the column given by its distance
  from the initial state, and the states of a column are reordered with the barycenter
  heuristic, sweeping forwards and backwards, until most transitions can be drawn as a
  straight line;
- **straight arrows are always preferred**. For every transition the program tries the
  straight line first and then wider and wider curves, discards any of them that would
  be drawn on top of a state, and keeps the one that crosses the fewest arrows already
  routed;
- the whole set of arrows is then **routed a second time**, now that the position of all
  the others is known, which removes the crossings the first pass could not foresee;
- two opposite transitions always get one arc each, on either side of the line, and
  self-loops are drawn in a reserved band above their state;
- only if no curve is clean does the transition take a free horizontal **lane** above
  (or below, when it goes backwards) every state it passes, turning aside in the gaps
  between columns;
- the view box is computed from what was actually drawn, so nothing is ever cut off.

For the automaton of the assignment this ends up with **no arrow crossing another one
and no arrow drawn over a state**, in both the NFA and the DFA.

The page also works completely **offline**.

## ✅ Worked example

Running `python main.py < input.txt` on the automaton of the assignment, the initial
state of `M` is `S = {3, 5}`, and:

- `δ({3,5}, a) = Δ(3,a) ∪ Δ(5,a) = {2,4} ∪ {1,5} = {1,2,4,5}`
- `δ({3,5}, b) = Δ(3,b) ∪ Δ(5,b) = ∅ ∪ {4} = {4}`

Only 7 of the 32 subsets are reachable:
`{3,5}`, `{1,2,4,5}`, `{4}`, `{1,5}`, `{4,5}`, `{5}` and `∅` — these are the ones
drawn in `output.html`.
